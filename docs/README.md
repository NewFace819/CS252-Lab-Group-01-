# Fitlens — Documentation

This directory contains documentation for the Fitlens project.

The purpose of this directory is to keep project documentation organized, accessible, and up to date throughout development.

## Documentation Structure

```text
docs/
├── README.md     # Overview of the documentation directory
├── team.md       # Team member names, member numbers, and roles
└── ui_mockup.png # UI design mockup for Fitlens Gym & Fitness Assistant
```

Additional documents may be added as the project develops.

## Available Documentation

### Team Information

See [team.md](team.md) for the project team members, their member numbers, and their assigned responsibilities.

### UI Mockup & Architecture Plan

See [ui_mockup.png](ui_mockup.png) for the visual mockup of the Fitlens gym and fitness assistant interface. Detailed architectural specifications and backend calling plans are documented in [ui/README.md](../ui/README.md).

### Project Setup and Usage

Refer to the [main README](../README.md) for installation instructions, environment setup, application execution, and testing procedures.

## Documentation Guidelines

To keep documentation clear and maintainable, contributors should:

- Write instructions in clear, concise English.
- Keep documentation consistent with the current implementation.
- Update relevant documents whenever project structure, setup procedures, or responsibilities change.
- Use relative links when linking to files within the repository.
- Verify that commands and instructions work before documenting them.

## Development Workflow

Documentation changes should follow the project's standard Git workflow:

1. Create a branch for the task.
2. Update the relevant documentation.
3. Verify file paths, links, and instructions.
4. Commit changes with a descriptive Conventional Commit message.
5. Submit a Pull Request for review before merging.

Example commit message:

```text
docs: update project documentation
```
